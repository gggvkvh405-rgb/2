# ByAzen — рабочий мессенджер (телефон + ПК)

Настоящий мессенджер: свой сервер, аккаунты по нику, личные диалоги, круги,
фото, голосовые, доставка в реальном времени, шифрование канала.

```
server/         → сервер: аккаунты, чаты, медиа, WebSocket (+ JSON-база)
app/            → клиент: PWA, адаптив (телефон/ПК), офлайн-оболочка
desktop/        → Electron-обёртка для .exe
concept.html    → бренд-презентация (идея, айдентика, AI-фото интерфейса)
tools/          → локальный сервер и тесты
BUILD.md        → сборка .exe / .apk / Docker
```

---

## Быстрый старт (2 минуты)

```bash
npm install
npm start            # http://localhost:8080/app/index.html
```

1. Откройте адрес — приложение само найдёт сервер на этом же хосте.
2. «Регистрация» → ник + пароль → вы внутри.
3. Дайте другу **адрес вашего сервера** и ник. Он регистрируется у себя,
   нажимает **＋ (Новый разговор)**, ищет вас по нику — и вы общаетесь.

В одной Wi-Fi сети достаточно адреса `http://<IP-компьютера>:8080`.
Из разных сетей — задеплойте сервер (ниже), получите `https://…` и укажите его в поле «Адрес сервера».

## Как сделать так, чтобы друг подключился из другой сети

Любой Node-хостинг с WebSocket. Самые простые:

**Render** (есть бесплатный тариф, репозиторий уже содержит `render.yaml`)
1. Запушьте репозиторий на GitHub.
2. Render → New → Blueprint → выберите репозиторий → Apply.
3. Через пару минут получите `https://byazen-xxxx.onrender.com`.
4. Этот адрес вводите у себя и у друга (поле «Адрес сервера»).

**Fly.io / Railway / VPS** — то же самое: команда запуска `npm start`, порт `8080`.

**Docker**

```bash
docker build -t byazen .
docker run -p 8080:8080 -v byazen-data:/data byazen
```

## Что умеет

| Функция | Детали |
| --- | --- |
| Аккаунты | ник (2–20 симв.), пароль хэшируется scrypt, токен сессии |
| Личные диалоги | поиск по нику, создание в один клик, дубликаты не создаются |
| Круги | закрытые группы до 20 человек, добавление по нику |
| Доставка | WebSocket, ack с галочками, авто-переподключение с backoff |
| Очередь | сообщение, отправленное без сети, уходит при восстановлении |
| Печатает… | индикатор в реальном времени, работает и в кругах (с именем) |
| Прочитано | отметки о прочтении в обе стороны |
| Фото | сжатие на устройстве → загрузка на сервер → просмотр на весь экран |
| Голосовые | запись с микрофона, загрузка, длительность, волна, воспроизведение |
| Реакции | эмодзи на сообщение, видно всем участникам |
| Ответы и удаление | цитата-ответ, удаление своих сообщений у всех |
| Профиль | имя, аватар (синхронизируется), акцентная тема |
| Тихие часы | расписание + уведомления рабочего стола |
| Присутствие | «в сети» у собеседника, точка состояния связи |
| Офлайн | service worker кэширует оболочку, данные — на сервере |
| Демо-режим | «Посмотреть демо без сервера» — локальные чаты-симуляция |

## Сборка приложений

```bash
npm run dist:win            # → release/ByAzen-Setup-1.0.0.exe + portable
npx cap add android && npx cap sync android
npm run mobile:apk          # → android/app/build/outputs/apk/debug/app-debug.apk
```

APK собирается из папки `app/` и обращается к вашему серверу по адресу,
который вводится на экране входа. Подписанный релиз — см. [BUILD.md](BUILD.md).
GitHub Actions (`.github/workflows/build.yml`) собирает `.exe`, `.apk` и проверяет сервер автоматически.

## Приватность — честно

- Пароли: `scrypt` с солью, в открытом виде не хранятся.
- Сообщения на сервере лежат **в открытом виде** в JSON-базе — сервер должен их доставлять.
  Текст на клиенте дополнительно шифруется в локальном кэше (AES-256-GCM, ключ устройства).
- Полное сквозное шифрование (E2EE) требует обмена ключами между устройствами —
  это следующий шаг; текущая версия — «сервер у вас под контролем», а не E2EE.
- Никакой аналитики и третьих сторон: ни одного внешнего запроса.

## Что дальше можно добавить

- E2EE на X25519 + AES-GCM (ключи в профиле, обмен при первом диалоге).
- Push-уведомления (FCM для APK, Web Push для PWA).
- Звонки на WebRTC.
- Голосовые комнаты и «исчезающие» сообщения.
